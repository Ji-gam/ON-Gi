# 품앗이온 가설 검증 로드맵 (3단계)

> 기술·제품 가설을 3단계로 나누고 각 단계를 **실행 → 측정 → 판정 → 개선**의 이터레이션으로 돌린다.
> 설계 상세는 [TECH_LOGIC.md](TECH_LOGIC.md), 재원·손익은 [유료] 문서. 여기서는 **무엇을 어떻게 틀렸다고 판정할지**만 다룬다.
>
> **1·2·3단계는 일정이 아니라 순서다.** 앞 단계가 참이어야 뒤 단계가 의미를 갖는다는 의존 관계일 뿐, 기간을 배정하지 않는다.
> **지금 실제로 하는 것은 §3.5의 H1-a 하나**이고, 2·3단계는 그 이후의 방향이다. 일정이 필요하면 [GANTT.md](GANTT.md)를 본다.

---

## 0. 시작 전 전제

### 0.1 가설이 아닌 것 — 실험 대상에서 제외

아래는 검증 대상이 아니라 **제약**이다. 지표가 나쁘게 나와도 완화하지 않는다.

| 제약 | 근거 |
|---|---|
| 야간 인원 상한 1:5 | [법률] · TECH_LOGIC §2.2 |
| `SAFETY` 태그(알레르기·투약 등) 하드 필터 | §3.3 |
| 신뢰 L3 = 단독위탁 게이트 | §7 |
| 아동 정보 동의·암호화·접근 로그 | 개인정보보호법 §22조의2 |
| 돌봄 교환 자체의 영구 무료 | [유료] |

**"전환율이 안 나오니 안전 게이트를 낮추자"는 개선안은 채택하지 않는다.** 이 경계를 처음에 못 박아두지 않으면, 지표 압박이 생겼을 때 가장 먼저 흔들리는 게 안전장치다.

### 0.2 공통 이터레이션 루프

```
[주 1회] 지표 계측 → 대시보드 갱신
[격주]   판정 회의 — 개선안 1개만 적용(동시 변경 금지: 무엇이 효과였는지 알 수 없다)
[단계 말] 게이트 판정 — 통과: 다음 단계 / 미달: 개선 1회전 추가 / 반증: 설계 재검토
```

- **한 번에 하나만 바꾼다.** 파라미터 두 개를 같이 움직이면 원인 귀속이 불가능해진다.
- 개선안은 반드시 TECH_LOGIC의 `Q-번호`(미결 항목)와 연결한다. 로드맵이 곧 미결 해소 계획이 되도록.
- 표본이 작은 초기에는 **비율보다 절대 건수**를 먼저 본다(20명 중 2명은 10%가 아니라 "2건"이다).

## 1단계 — "엇갈린 시간이 실제로 존재하는가"

### H1 (기술 가설)

> 교대근무자끼리는 근무 시간이 엇갈리므로, **근무표만 넣으면 상보 후보가 자동으로 나온다.**

이게 서비스의 첫 번째 기둥이다. 여기가 무너지면 매칭 알고리즘·신뢰·유료화가 전부 의미 없다. 그래서 **가장 먼저, 가장 싸게** 검증한다.

### 실행 (P0 ①~⑤)

프로필·아동 등록 → 근무표 업로드(엑셀/디지털 PDF) → 검증 게이트 → 48슬롯 마스크 → Stage 1 필터 + Stage 2 랭킹 + 근거 문장. **매칭 성사까지 안 가도 된다** — "후보가 화면에 뜨는가"까지가 1단계다.

### 측정

| 지표 | 목표(가정) | 의미 |
|---|---|---|
| **상보 후보 보유율** | 등록자의 **60%** 이상이 후보 1명 이상 | H1의 직접 반증 지표 |
| 1인당 평균 상보 슬롯 수 | 주당 6슬롯(3시간) 이상 | 후보가 "있다"와 "쓸 만하다"는 다르다 |
| 근무표 확정률 | 업로드 대비 `confirmed_at` **80%** 이상 | 파싱이 실용적인가 |
| 셀 '확인 필요' 비율 | 10% 이하 | 사용자 수정 부담 |
| `matches/search` P95 | 800ms | §12.2 예산 |

### 판정과 개선 이터레이션

| 관측 | 원인 가설 | 개선안 (하나씩) |
|---|---|---|
| 후보 보유율 낮음 | 수면 회복 구간이 과하게 잡혀 `free_mask`가 비었다 | **8슬롯(4h) 재조정** → Q-4 해소 |
| 〃 (재조정 후에도) | 밀도 부족 — 사람이 없다 | 무료 반경 `R0`을 파일럿 한정 임시 확대(유료화 검증은 3단계로 미룸) |
| 〃 (반경 확대 후에도) | 모집 단위가 틀렸다 | **개인 모집 → 직장 단위 모집으로 전환.** 같은 직장 반대조가 가장 확실한 상보 쌍이다 ([흐름] 직장 기반 Pod) |
| 확정률 낮음 | 파싱 실패 | 라벨 사전 확충(규칙 기반 우선) → 그래도 실패하면 Tier B LLM 위임 범위 확대 |
| 후보는 있는데 클릭이 없음 | 근거 문장이 설득되지 않음 | XAI 템플릿 문구 개선 → 가중치 조정(Q-12)은 그 다음 |

**반증 조건**: 위 개선을 모두 돌린 뒤에도 상보 후보 보유율이 **40% 미만**이면 H1이 틀린 것이다. → "교대근무자 간 상보성"이 아니라 **다른 매칭 축**(단순 근접·시간대 선호)으로 제품 전제를 재검토한다.

**게이트**: 1단계 성공 기준 충족 → 2단계 진입.

## 2단계 — "후보가 있으면 실제로 맡기는가"

### H2 (제품 가설)

> 상보 후보가 보이면, 부모는 **신뢰 단계를 밟아 실제로 아이를 맡긴다.**

1단계가 "기술이 되는가"라면 2단계는 **"마음이 움직이는가"** 다. 아동 돌봄에서 가장 크고 가장 검증이 안 된 가설이며, 여기가 맘카페·당근과 갈리는 지점이다.

### 실행 (P0 ⑥~⑨)

요청 → 수락 → 에스크로 홀드 → 확정 → 체크인/아웃 + 돌봄 일지(의무) → 리뷰·별점(돌봄마음) → **신뢰 상태머신 L1→L2→L3**.

### 측정

| 지표 | 목표(가정) | 의미 |
|---|---|---|
| **L1→L2 전이율** | 8주 내 **30%** 이상 | 공개장소 공동육아 1회를 실제로 하는가 |
| **L2→L3 전이율** | 8주 내 **10%** 이상 | 단독위탁까지 가는가 — H2의 핵심 |
| 매칭 성공률 | [유료] 목표 50% 대비 **20%** | 6개월차 Go/No-Go 기준 |
| 노쇼율 | 10% 이하 | 포인트 에스크로가 작동하는가 |
| 돌봄 일지 작성률 | 95% 이상 | 의무인데 안 쓰면 분쟁 판정 근거가 사라진다 |
| 이행 확인 응답률 | 80% 이상 | 감시받는 느낌으로 이탈하는지의 신호 |

### 판정과 개선 이터레이션

| 관측 | 원인 가설 | 개선안 (하나씩) |
|---|---|---|
| L1에서 정체 | 첫 만남의 문턱이 높다 | **팀이 공개장소 세션을 직접 주선**(운영자 수동 개입 API). Pod 대기열을 묶어 동시 오픈 |
| 〃 | 상대를 고를 근거가 부족 | 리뷰 열람 무료 전환 검토 — 단 재열람 무과금 원칙 유지 |
| L2→L3 정체 | 단독위탁 심리 장벽 | **게이트 완화 아님(§0.1).** 대신 L2 세션의 성공 경험을 노출(돌봄마음·일지 요약) |
| 이행 확인 응답률 낮음 | 제한이 빡빡해 감시로 느낀다 | 간격·횟수 조정 → Q-15 해소. **단 심야 1회 제한은 불변** |
| 노쇼율 높음 | 포인트 홀드 유인이 약하다 | 홀드 규모 상향 → 그래도 안 되면 현금 에스크로(Phase 2) 앞당김 검토 |
| 돌봄마음 분포가 4점대에 몰림 | 별점이 변별력이 없다 | `PINK` 밴드 `4.5~5.0` 확대(Q-10) + 노출 임계 조정(Q-3) |

**반증 조건**: 개선 후에도 L2→L3 전이가 **3% 미만**이면, "이웃에게 아이를 단독으로 맡긴다"는 전제 자체가 시장에서 성립하지 않는 것이다. → **동반 돌봄(부모 동석) 전용 서비스로 피벗**을 검토한다. 이건 축소가 아니라 다른 제품이다.

**게이트**: L2→L3 10% + 매칭 성공률 20% → 3단계 진입. (이 지점이 [유료]의 Go/No-Go 판단 근거가 된다.)

## 3단계 — "관계가 지속되고, 일부는 돈을 내는가"

### H3 (비즈니스 가설)

> 한 번 성공한 관계는 **반복되고 Pod로 발전하며**, 일부 사용자는 **반경 확장에 포인트·현금을 쓴다.**

1회성 거래로 끝나면 당근과 다를 게 없고([흐름]), 재원이 없으면 무료 운영이 지속되지 않는다([유료]).

### 실행 (P1)

릴레이 체인 · 반복 자동 매칭 · Pod 대기열 완성 · 반경 확장 포인트 경로 + 거리 밴드 알림 · 원장 정합성 배치.

### 측정

| 지표 | 목표(가정) | 의미 |
|---|---|---|
| **재매칭률** | 완료 세션의 **30%** 이상이 동일 상대와 2회차 | 지속성 — H3의 핵심 |
| **완성 Pod 수** | **1개 이상**(4~6가구) | [유료]가 정의한 진짜 목표 = 그룹 밀도 |
| 호혜 균형 | `take-give > 20h` 사용자 비율 10% 이하 | 한쪽만 받는 구조가 되는지 |
| 반경 확장 사용률 | 포인트 경로 **5%** 이상 | 유료 WTP의 선행 지표 |
| 범위 밖 요청 수락률·노쇼율 | 노쇼율이 범위 내 대비 +5%p 이내 | §10.3 나) 안이 실제로 작동하는가 |
| 릴레이 성립률 | 야간 공백 요청의 30% 이상 완전 피복 | 릴레이가 실용적인가 |

### 판정과 개선 이터레이션

| 관측 | 원인 가설 | 개선안 (하나씩) |
|---|---|---|
| 재매칭률 낮음 | 반복 매칭 자동화가 안 보인다 | 고정 파트너 제안 UI 강화 → 근무표 변경 시 재제안 타이밍 조정 |
| Pod 미완성 | 4~6가구를 못 채운다 | 팀 직접 조율 유지 + 직장 단위 모집(1단계 학습 재사용) |
| 반경 확장 사용률 낮음 | 단가·기간이 안 맞다 | 포인트 단가·유효기간 조정 → Q-19 해소 |
| 〃 | 애초에 넓힐 이유가 없다(=밀도가 충분) | **좋은 신호다.** 유료화 축을 반경에서 다른 편의 기능으로 재검토 |
| 범위 밖 노쇼율 급증 | 거리 고지가 부족하거나 `ADJACENT`가 비현실적 | 문구 강화 → 그래도 높으면 `ADJACENT` 밴드 폐기 |
| 유료 전환 추정 미달 | 가격 문제 | 월 1,990원 재검토 + 12개월 손익 재계산 → Q-18 해소. **무료 반경 축소는 금지**(핵심 가치 영구 무료 원칙 위반) |

**반증 조건**: 재매칭률 **15% 미만**이면 "지속 관계" 전제가 틀린 것 → 1회성 긴급 돌봄 중개로 제품 정의를 좁힌다.
전환율이 [유료]의 가정(5%)의 절반 이하이면, 부분유료화는 재원 계획에서 빼고 **B2G·제휴 중심으로 재설계**한다. [유료]도 "부분유료화는 안전마진을 키우는 장치이지 성장 실패를 구원하지 못한다"고 이미 결론 냈다.

## 3.5 이번에 반드시 달성할 가설 1개 — **H1-a**

세 단계를 다 검증할 시간은 없다. **하나를 골라 끝까지 닫는다.** 고른 것은 1단계의 기술 가설이다.
**가설은 끝까지 이 하나뿐이다.** 아래 개정은 새 가설을 추가한 것이 아니라 같은 가설의 문장을 데이터에 맞춰 고친 것이다.

> **H1-a (v3 · 최종형)**: 공공데이터로 확인된 밀도 조건 아래에서, **반경·근무 상보성·가치관 세 축을 결합한 매칭**은 단순 시간 겹침 방식보다 **유의하게 나은 후보를 낸다.**

**전제(가설 아님, 이미 닫힌 입력값)**: 반경 1km 안에 최소 밀도의 영유아 가구가 있고, 공공 아이돌봄의 미충족은 인력 총량 부족으로 설명되지 않는다.

### 개정 이력 — 문장이 두 번 바뀌었다

**이 이력 자체가 산출물이다.** 멘토링에서 요구한 "실행 → 개선 이터레이션"이 여기 그대로 남아 있다.

| 버전 | 문장 | 왜 바꿨나 |
|---|---|---|
| **v1** | 반경 1km 안에 영유아 가구가 밀집해 있고, 공공 돌봄에 대기가 쌓여 있다 | 근무표 50장 수집이 불가능해 밀도 검증으로 전환한 직후의 형태 |
| **v2** | 〃 + 미충족은 **인력 총량 부족이 아니다** | 실측해 보니 원래 문장보다 강한 게 나왔다. 즉시 투입 가능한 돌보미 18,722명이 있는데도 대기가 42번 중 41번 늘었다. "대기가 있다"는 통계만 보면 참이라 **반증할 수 없는 서술**이었고, "인력 부족이 아니다"는 원인 주장이라 반증 가능하다 |
| **v3** | 위를 **전제로 내리고**, 세 축 매칭이 베이스라인을 이긴다는 **기술 명제**로 올림 | v2까지는 전부 **시장 가설**이었다. 공공 API를 호출해 CSV를 집계한 것뿐이고 매칭 엔진은 한 줄도 안 걸렸다. 멘토링 과제는 **기술/제품 가설**이므로 검증 대상을 엔진으로 옮긴다 |

**v2 → v3에서 공공데이터의 지위가 바뀐다.** 증명할 대상이 아니라 **엔진에 넣을 입력 조건**이다. 이미 닫혔으므로 가설로 둘 이유가 없고, 시뮬레이션의 현실성을 담보하는 근거로 쓰는 편이 훨씬 강하다 — 합성 밀도가 아니라 **실제 지역의 밀도**를 넣고 돌린다.

> **용어 주의**: 개정을 `H1-b`처럼 새 번호로 부르지 않는다. 번호가 늘면 "가설 1개" 원칙이 흔들려 보인다. 문서·발표·위젯 전부 **H1-a** 하나로 쓰고, 필요하면 버전만 붙인다.

### 스택의 어느 층이 어디서 판정되는가

| 스택 요소 | 판정 근거 | 사용자 필요 |
|---|---|---|

**여섯 중 다섯은 파일럿 참여자 없이 닫힌다.** 그래서 H1-a v3의 검증 대상을 랭킹 `S`로 잡았다 — 제품의 기술적 차별점을 대표하면서, 사람을 못 모아도 결론이 난다. 지표 정의는 [AI_MATCHING_EVAL.md](AI_MATCHING_EVAL.md) `E4`.

### 왜 "근무표 수집"이 아니라 "밀도"인가

처음에는 근무표 50장을 모아 상보성을 계산하려 했으나 **두 가지 이유로 폐기했다.**

1. **근무표는 구할 수 없는 자료다.** 병원·기관 내부 문서이고 동료의 이름·근무시간이 들어 있는 **제3자 개인정보**다. 50장을 정당하게 수집할 경로가 없다.
2. **합성 데이터로 대체하면 동어반복이 된다.** 3교대 규칙으로 생성한 패턴끼리 엇갈리는 것은 규칙상 당연하다. "D조와 N조는 시간이 겹치지 않는다"를 증명해봐야 아무것도 입증되지 않는다.

**진짜 불확실한 것은 패턴이 아니라 사람 수다.** 교대 패턴이 엇갈린다는 건 자명하고, 실제로 모르는 건 *"우리 동네 1km 안에 다른 조로 일하는 교대근무 부모가 몇 가구나 있는가"* 다. 이건 근무표가 아니라 **공공데이터로 답할 수 있다.**

**동시에 세 가지 한계가 드러났고, 기획서에는 이것까지 같이 적는다.**

1. **`대기정회원수`는 2023-07을 끝으로 집계가 중단됐다.** 이후 월은 0으로 채워져 있다. 위 수치는 *최신*이 아니라 *마지막으로 공표된* 값이다. 2025-08부터 `승인대기회원수`(2026-02 기준 2,941명)가 새로 잡히지만 **정의가 달라 이어 붙일 수 없다**
2. **2025-06에 정회원 정의가 바뀌었다** (343,406 → 101,125, -71%). 같은 달 이후 휴면회원 71만 명이 별도 필드로 잡힌다. **이 구간을 가로질러 증감을 말하면 안 된다**
3. **야간 필드는 끝내 없었다.** 위 격차가 시간대 때문인지 총량 때문인지 공공데이터로는 갈라낼 수 없다 → 설문으로 보완(아래 ①)

> **단위 주의 — 대기는 가구 수, 공급은 사람 수다.** 27,519 ÷ 18,722 = 0.68을 "1인당 0.68명이라 인력이 부족하다"로 읽으면 안 된다. 돌보미 1명은 여러 가구를 맡는다(실제 1인당 13.3가구). 이 나눗셈을 그대로 발표에 쓰면 바로 반박당한다.

> **그래서 주장을 이렇게 좁힌다.** "공공 아이돌봄에 미충족 수요가 있고, 그것이 인력 총량 부족으로는 설명되지 않는다"는 **정부 통계로 입증됐다** — 즉시 투입 가능한 인력이 1만 8천 명 있는데도 대기가 43개월간 거의 매달 늘었다. **"있는 사람과 기다리는 가구가 서로 안 붙는다"가 실측된 사실이다.**
> 반면 **"안 붙는 원인이 야간·교대 시간대다"는 아직 가설이며 설문으로 검증한다.** 조건 불일치·지역 불일치·통계상 미삭제 등 다른 원인과 공공데이터로는 갈라낼 수 없다. 앞은 실측, 뒤는 가설 — 둘을 섞어 쓰지 않는다.
>
> **이 구분이 제품 정의를 가른다.** 진짜 인력 부족이라면 해법은 "돌보미 증원"이고 그건 예산 문제라 우리가 낄 자리가 없다. 붙지 않는 것이 문제라면 해법은 **연결 방식**이고, 그건 소프트웨어가 할 수 있는 일이다.

### 검증 설계 (3단)

**① 밀도와 미충족 수요 — 공공데이터 (핵심)**

- 어린이집 **현원수 + 위경도**를 500m 격자에 얹어 → **반경 1km 안 영유아 가구 밀도**
- **대기정회원수**(신청했으나 못 받는 가구) 대 **바로연계가능 돌보미 수**(당장 투입 가능한 인력) → **공공 돌봄의 미충족 수요**
- 산출: **지역별 밀도 지도 + 미충족 지수**

> 원래는 지역별고용조사로 교대근무자 수를 추정하려 했으나, 확보 목록에 없고 시군구 단위 교대 구분 여부도 미확인이라 **핵심 경로에서 뺐다**(Q-22). 교대근무자 밀도는 병원·소방서 위치와 종사자 통계로 **보조 추정**하되, 없으면 없는 대로 리포트에 적는다.
> **야간 조건은 공공데이터가 아니라 설문(교대근무자 우려 조사)으로 보완한다.** 시간대 가정을 빼는 대신 실측값으로만 말한다.

**② 상보성 시뮬레이션 — 합성 패턴 (보조)**

실제 3교대 근무규칙(연속 야간 제한, N→D 금지, 주당 근무시간 상한)으로 패턴을 생성하고, ①의 밀도(20/30/50가구)를 대입해 **후보 보유율 곡선**을 그린다.
**이 단계의 목적은 상보성 증명이 아니라 "몇 명이 모여야 하는가"의 임계 밀도 산출이다.** 합성이라는 한계를 리포트에 명시한다.

**③ 실물 소수 검증 — 3~5장**

팀·지인 중 교대근무자에게 **본인 열만 남기고 동료 정보를 마스킹**한 근무표를 받아, 합성 패턴이 실제와 얼마나 다른지 확인한다. 성능 측정이 아니라 **①②의 가정 검증**이 목적이므로 소수로 충분하다.

### 산출물

1. **지역별 밀도 지도** — 파일럿 지역 선정(Q-9)의 근거
2. **임계 밀도 곡선** — Pod 정원(4~6가구)과 모집 목표의 근거
3. 합성 패턴 시뮬레이터 + B0~B3 베이스라인 비교
4. 데모: 근무표 업로드 → 후보 + 근거 문장 (실물 3~5장으로)

**임계 밀도가 핵심 산출물이다.** "60%가 나왔다"보다 **"한 지역에 N가구가 모이면 서비스가 성립하고, 그 N을 채울 수 있는 지역이 여기 있다"** 가 훨씬 강한 주장이고, 이게 곧 파일럿 지역 선정과 모집 목표의 근거가 된다.

**반증선 (v3의 핵심)**: 세 축 매칭이 `B3`(한 방향 피복) 대비 Precision@5에서 **+5%p 미만**이면, "가치관 축이 매칭 품질을 올린다"는 주장이 성립하지 않는다. → 가치관 유사도를 랭킹에서 빼고 **탐색 필터로만** 쓰는 쪽으로 제품을 단순화한다. 이건 실패가 아니라 **가중치 설계가 틀렸다는 결론**이며, 그 자체가 보고할 만한 결과다.

**미달 시**: 임계 밀도를 충족하는 지역이 없다면 반경 `R0`(800m~1km) 전제가 틀린 것이다. → 반경 확대가 아니라 **직장 단위 Pod로 전환**(같은 병원 다른 조는 거리와 무관하게 상보 쌍이다). 이건 [흐름]이 이미 "일반 동네 Pod보다 훨씬 빠르게 활성화될 가능성이 높다"고 짚은 경로다.
