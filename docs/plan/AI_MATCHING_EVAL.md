# AI 매칭 — 검증 과정과 성능 평가 지표

> 대상: [TECH_LOGIC.md](TECH_LOGIC.md) §3(매칭 엔진), §4(근무표 인식·RAG)
> 목적: "AI가 매칭한다"를 **측정 가능한 명제**로 바꾸고, 무엇을 어떻게 재서 성능을 주장할지 정한다.
>
> **가설은 1개다.** 달성 대상 가설은 [HYPOTHESIS_ROADMAP.md §3.5](HYPOTHESIS_ROADMAP.md)의 **H1-a** 하나뿐이고, 이 문서의 `E1~E4`는 독립된 가설이 아니라 **H1-a를 입증하기 위한 평가 항목**이다.

## 0. 먼저 — 무엇이 AI이고 무엇이 아닌가

성능 평가를 설계하려면 이 구분이 선행돼야 한다. 섞으면 "알고리즘이 정확한 것"과 "모델이 잘 맞히는 것"을 같은 지표로 재게 된다.

| 구성요소 | 성격 | 검증 방법 |
|---|---|---|
| 가치관 유사도 `V` (양육관 8문항 벡터, 바움린드 2축 기반) | **학습 모델** | 인간 판단과의 상관 (§3) |
| 선호 태그 자유서술 임베딩 | **학습 모델** | 동의어 검색 품질 (§3) |
| 돌봄 안전 정보 RAG | **학습 모델 + 검색** | Recall@k, 출처 정확도 (§4) |
| 근무표 PDF 파싱 | 규칙 기반 + Tier B LLM | 셀 단위 정답 대조 (§2) |
| **랭킹 `S = 0.35V+0.25M+0.20R+0.20B`** | **학습 모델 아님 — 가중합 휴리스틱** | 프록시 라벨 기반 순위 품질 (§5) |
| 상보성 `harmonic_mean(popcount)` | 결정론적 연산 | 단위 테스트 (정확성은 자명) |
| 릴레이 구간 피복 · Set Cover | **최적화 알고리즘** | **최적성 증명 + 반례 테스트** (§6) |

**핵심**: 우리 시스템의 매칭 품질은 대부분 **알고리즘 정확성 + 가중합 설계**에서 나오고, 학습 모델은 `V`·태그·RAG에 국한된다. 이걸 정직하게 밝히는 것이 "AI를 썼다"고 뭉뚱그리는 것보다 기술 신뢰도가 높다. 랭킹 가중치는 파일럿 데이터로 **튜닝**하는 것이지 학습하는 것이 아니다(Q-12).

## 1. 검증 과정 (3 트랙)

```
트랙 A  오프라인 — 정답 라벨을 만들 수 있는 것 (파싱, RAG, 알고리즘)
        → 파일럿 이전에 완료 가능. 개발 중 회귀 테스트로 상시 실행

트랙 B  전문가 판정 — 정답이 없는 랭킹 품질의 콜드스타트 대응
        → 팀 5인이 후보 쌍을 블라인드 평가해 의사 정답셋 구축

트랙 C  온라인 — 실사용 행동을 프록시 라벨로 사용
        → 파일럿 개시 후. 수락·완료·재매칭이 곧 정답 신호
```

트랙 B가 필요한 이유: 랭킹은 **정답이 원래 없다.** 파일럿 전에는 사용자 행동 데이터도 없으므로, 그 공백을 전문가 판정으로 메우고 트랙 C가 쌓이면 교체한다.

## 2. 근무표 파싱 (트랙 A)

**평가 항목 E1** — 규칙 기반 사전 + PyMuPDF 좌표 추출만으로 **외부 API 없이** 실용 정확도가 나온다.

### 2.0 데이터 제약 — 실물 근무표는 구할 수 없다

근무표는 병원·기관 **내부 문서**이고 동료의 이름·근무시간이 들어 있는 **제3자 개인정보**다. 30장을 정당하게 수집할 경로가 없으므로 **"실물 30장 라벨링"은 폐기**하고 3계층으로 대체한다.

| 계층 | 데이터 | 정답 출처 | 언제 |
|---|---|---|---|
| **L1 합성 벤치마크** | 팀이 서식을 모방해 생성한 근무표 50장 | **생성 시점에 정답을 이미 안다**(라벨링 비용 0) | 지금 |
| **L2 실물 소수** | 지인 교대근무자에게 **본인 열만 남기고 마스킹**한 3~5장 | 제공자 본인 확인 | 지금 |
| **L3 사용자 확정본** | 파일럿 실사용자가 업로드하고 검증 게이트에서 수정한 근무표 | **사용자가 확정한 값이 곧 정답** | 파일럿 후 |

**L3가 본 평가셋이다.** 검증 게이트(§TECH_LOGIC 4)가 이미 "사용자가 셀을 확인·수정하고 `confirmed_at`을 찍는" 구조이므로, **수정된 셀 = 파서의 오답**이 자동으로 기록된다. 별도 라벨링이 필요 없고 데이터는 실물이다. 원래 UX로 만든 장치가 평가 인프라 역할을 겸한다.

### 2.1 계층별 지표

**L1 (합성) — 파서 회귀 테스트용**

| 지표 | 목표 |
|---|---|
| 셀 정확도 | 98% (합성이므로 높게 잡는다) |
| 표 구조 복원율 | 95% |
| 라벨 정규화 커버리지 | 90% (나머지만 Tier B LLM 위임) |

**L1 점수를 성능 근거로 발표하지 않는다.** 우리가 만든 문서를 우리 파서로 읽은 결과라 과대평가가 확실하다. 용도는 **회귀 방지**(CI에서 상시 실행)뿐이다.

**L2 (실물 소수) — 과대평가 보정**

핵심 산출물은 정확도 자체가 아니라 **L1 대비 하락폭**이다. 예: L1 98% → L2 82%면 합성 벤치마크가 16%p 과대평가한다는 뜻이고, 이 격차가 곧 병합셀·비정형 서식 같은 실물의 지저분함이다. **격차를 리포트에 그대로 적는다.**

**L3 (사용자 확정본) — 진짜 지표**

| 지표 | 정의 | 목표 |
|---|---|---|
| **셀 수정률** | 사용자가 고친 셀 / 전체 셀 | **5% 이하** |
| **확정 도달률** | `confirmed_at` 찍힌 문서 / 업로드 문서 | **80% 이상** |
| **'확인 필요' 재현율** | 사용자가 고친 셀 중 시스템이 미리 표시했던 비율 | **95% 이상** |
| '확인 필요' 정밀도 | 표시한 셀 중 실제로 수정된 비율 | 60% 이상 |

**재현율을 정밀도보다 높게 잡는 이유**: 놓친 오답 1건은 **없는 가용 시간**을 만들고, 그 시간에 아이를 맡길 사람이 없다. 과잉 확인 요청은 귀찮은 정도지만 놓친 오답은 사고로 간다. 비대칭 비용이므로 지표도 비대칭으로 설계한다.

**확정 도달률이 최종 지표인 이유**: 셀 정확도가 90%여도 사용자가 포기하고 확정을 안 누르면 서비스는 작동하지 않는다. 반대로 정확도가 낮아도 수정이 쉬워 확정까지 가면 문제가 없다. **파싱은 정확도 경연이 아니라 확정 도달을 위한 수단이다.**

**Tier B(LLM) 판정**: 사전 커버리지가 90% 미만일 때만 위임 범위를 넓힌다. LLM을 먼저 쓰고 사전을 나중에 채우는 순서는 금지 — 재현성과 비용이 모두 나빠진다.

## 3. 가치관 임베딩 `V` (트랙 A + B)

**평가 항목 E2** — 양육관 8문항 벡터(바움린드 온기·통제 2축을 각 4문항으로 구성)의 코사인 유사도가 **사람이 느끼는 "육아 스타일이 맞다"** 와 상관한다.

| 지표 | 방법 | 목표 |
|---|---|---|
| **인간 판단 상관** | 팀 5인이 프로필 쌍 50개를 1~5점으로 블라인드 평가 → 코사인 유사도와 **Spearman 상관** | **ρ ≥ 0.5** |
| 평가자 간 신뢰도 | Krippendorff's α | 0.6 이상 |
| 벡터 분산 | 전체 프로필의 유사도 분포 표준편차 | 0.15 이상 |

> **지표 변경 (2026-08-07)**: 랭킹 품질의 주 지표를 `Precision@5`에서 **피복률@5**로 바꾼다. 릴레이는 순위가 아니라 **조합**을 내놓으므로 "상위 5명 중 몇 명이 정답인가"가 성립하지 않는다. 새 정의는 **상위 5명 안에서 최대 3명을 조합해 내 근무 시간의 몇 %를 덮는가**이며, **호혜 충족률**(나를 도운 사람 중 내가 되갚을 수 있는 비율, 목표 95%)과 **반드시 함께** 본다 — 피복률만 걸면 한쪽이 받기만 하는 조합으로 점수를 올릴 수 있다. 실측은 [EXPERIMENT_RESULTS.md](EXPERIMENT_RESULTS.md) §2-e.

**분산 지표가 중요하다.** 모든 쌍의 유사도가 0.9대에 몰리면 `V`는 변별력이 없고, 랭킹의 35%가 사실상 상수가 된다. 이 경우 8문항 설문 자체를 재설계해야 한다. 문항 초안과 분산 점검 절차는 [VALUE_SURVEY.md](VALUE_SURVEY.md).

**평가자 간 신뢰도가 낮으면** 사람도 합의하지 못하는 개념이라는 뜻이므로, `V`의 가중치 0.35를 낮추고 `M`(상보성) 비중을 올리는 것이 정직한 대응이다.

## 4. 안전 정보 RAG (트랙 A)

**평가 항목 E3** — 공공기관 발간 자료 색인만으로 **생성 없이** 실용적인 답이 나온다.

**데이터셋**: 실제 발생할 질의 **30개**(예: "생후 22개월 / 견과류 알레르기 / 야간 돌봄"), 각 질의에 정답 문서·구간을 팀이 라벨링.

| 지표 | 목표 |
|---|---|
| **Recall@5** | **90%** — 정답 스니펫이 상위 5개 안에 있는가 |
| MRR@5 | 0.7 |
| 출처 표기 정확도 | **100%** (스니펫과 출처가 어긋나면 즉시 실패) |
| 증분 재색인 정합성 | 원문 변경 후 재색인 시 구버전 잔존 0건 |

**Tier A는 생성하지 않으므로 환각률 지표가 없다.** 이것이 이 설계의 요점이다 — 아동 응급 정보에서 생성을 빼는 것은 열화가 아니라 **평가 항목 하나를 원천 제거**하는 선택이다.

## 5. 랭킹 `S` — 핵심 성능 평가 (트랙 B → C)

**평가 항목 E4** — `S`로 정렬한 상위 후보가 **거리순·시간겹침순 같은 단순 기준보다 실제로 더 수락된다.**

E4는 이 서비스의 기술적 차별점 전체를 대표하며 H1-a 성공 기준에 직접 들어간다. 반드시 **베이스라인 대비**로 주장해야 한다.

### 5.1 베이스라인

| # | 기준 | 확인하려는 것 |
|---|---|---|
| B0 | 무작위 | 하한선 |
| B1 | 거리순 (H3 근접) | 당근·맘카페 수준 |
| B2 | **단순 시간 겹침** (`A.free ∩ B.free` 크기순) | **엇갈림(상보성)이 겹침보다 나은가** |
| B3 | `S` 전체 | 우리 안 |

**B2가 가장 중요한 대조군이다.** "같이 비는 시간이 많은 사람"과 "내가 일할 때 비는 사람"은 다르며, 후자가 낫다는 것이 §3.2의 전제다. B3가 B2를 못 이기면 상보성 설계의 근거가 무너진다.

### 5.2 평가 지표

| 지표 | 정의 | 목표 |
|---|---|---|
| **Precision@5** | 상위 5명 중 '적합' 판정 비율 | B2 대비 **+15%p** |
| **NDCG@10** | 순위 가중 적합도 | B2 대비 **+0.1** |
| MRR | 첫 적합 후보의 역순위 | 0.5 이상 |
| 후보 0명 비율 | Stage 1 통과자가 없는 요청 비율 | 20% 이하 |

'적합' 라벨은 트랙 B에서는 전문가 판정, 트랙 C에서는 **수락(1차) → 완료(2차) → 재매칭(3차)** 순으로 가중한다. 재매칭이 가장 강한 정답 신호다.

### 5.3 어블레이션 — 각 항이 실제로 기여하는가

`S`에서 항을 하나씩 빼고 Precision@5를 잰다.

| 조건 | 확인 |
|---|---|
| `−V` | 가치관이 실제로 수락에 영향을 주는가 |
| `−M` | **상보성이 없으면 얼마나 나빠지는가** (핵심) |
| `−R` | 평판이 필요한가 |
| `−B` | 호혜 균형이 매칭 품질에 기여하는가, 아니면 공정성 장치일 뿐인가 |

기여도가 음수인 항은 가중치를 0으로 내리는 것이 아니라 **왜 음수인지 먼저 본다.** 예를 들어 `−B`가 더 좋게 나온다면, `B`는 품질이 아니라 **네트워크 생존을 위한 의도적 손해**이므로 유지하고 그 사실을 명시한다.

### 5.4 통계적 검정력 — 정직하게 짚을 것

파일럿 목표가 250명이므로 **A/B 테스트는 검정력이 부족하다.** 매칭 요청이 월 수십 건 규모면 15%p 차이를 유의하게 검출할 표본이 안 나온다. 따라서:

- **오프라인 리플레이**를 주 수단으로 한다 — 동일 요청 로그에 대해 B0~B3를 모두 돌려 순위를 비교(사용자 노출 없음)
- 온라인이 필요하면 A/B가 아니라 **인터리빙**(두 랭킹을 섞어 한 화면에 노출 후 클릭 비교) — 같은 사용자 내 비교라 표본 효율이 훨씬 높다
- 결과를 보고할 때 **표본 수와 신뢰구간을 함께 적는다.** "B2보다 18% 높았다(n=23)"는 주장이 아니라 관찰이다

## 6. 알고리즘 정확성 (트랙 A) — AI가 아니라 증명 대상

| 대상 | 검증 | 목표 |
|---|---|---|
| **릴레이 구간 피복** | EFT 반례 포함 케이스 20개 회귀 테스트 | **완전 피복률 100%** (해가 존재하면 반드시 찾는다) |
| 릴레이 vs EFT | 동일 입력에서 공백 발생 건수 비교 | EFT 대비 공백 0건 |
| Set Cover 완전탐색 | greedy 결과와 대조 | 완전탐색이 항상 ≤ greedy 인원 수 |
| 상보성 계산 | 비트마스크 vs 나이브 구간 연산 | 완전 일치 |
| XAI 근거 문장 | 동일 입력 100회 반복 | **출력 100% 동일**(결정론) |

**여기서 목표는 "높은 점수"가 아니라 "100% 또는 반례 없음"이다.** 확률적 품질이 아니라 정확성 문제이기 때문이다. 릴레이가 90% 맞다는 것은 10%의 밤에 아이가 혼자 남는다는 뜻이다.

## 7. 성능(속도) 예산

| 대상 | 목표 | 측정 조건 |
|---|---|---|
| `POST /matches/search` | **P95 800ms** | 후보 풀 500명, 동시 20 요청 |
| 내역 | H3 조회 50 + 비트마스크 30 + 코사인 20 + 집계 100 + 직렬화·근거 50 ms | |
| `POST /matches/relay-plan` | P95 1s | 후보 200명 |
| 근무표 파싱 (비동기) | 1장 30s 이내 | Celery, 요청 경로 예산 제외 |
| 임베딩 서빙 메모리 | ~1.1GB 상주 | 데모 노트북 사양 확인(Q-14) |

부하 테스트 조건을 명시하지 않은 P95는 의미가 없다. **"후보 풀 500명, 동시 20 요청"을 함께 적는다.**

## 8. 산출물

1. `tests/eval/` — 트랙 A 전체를 pytest로. **CI에서 상시 실행**(회귀 방지)
2. 라벨셋 3종 — 합성 근무표 50장(L1, 생성 시 정답 보유) + 마스킹 실물 3~5장(L2) / 프로필 쌍 50개(전문가 점수) / RAG 질의 30개(정답 구간)
3. 리플레이 하네스 — 요청 로그에 B0~B3를 돌려 지표를 뽑는 스크립트
4. 평가 리포트 — 지표·표본 수·신뢰구간·베이스라인 대비. 발표 자료의 근거

**우선순위**: §6(알고리즘 정확성) → §2 L1·L2(파싱) → §5(랭킹) 순. 앞 둘은 파일럿 없이 지금 할 수 있고, 랭킹과 §2 L3는 데이터가 쌓여야 한다.

**발표 시 주의**: L1(합성) 점수를 성능 근거로 제시하지 않는다. 실물 없이 낸 숫자를 실물 성능처럼 말하는 순간, 나머지 지표의 신뢰도까지 함께 잃는다. L1은 회귀 테스트, L2는 격차 보정, **L3가 본 지표**임을 명시한다.
